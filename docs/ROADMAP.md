# ACE roadmap

## Phase 0 — Repository rehabilitation

- Establish ACE product and engineering instructions
- Separate application code from domain data and persistence
- Add type-checking, production builds, and deployment workflows
- Remove hard-coded assumptions tied to the old repository name
- Keep credentials and production data out of the repository

## Phase 1 — Working private command center

- Persistent projects, decisions, memories, approvals, and activity history
- Working create and edit flows
- Daily briefing generated from ACE data
- Search across the operating system
- Clear demo/live integration labeling

## Phase 2 — Google operating layer

- Google authentication
- Calendar read access and scheduling proposals
- Gmail triage and draft preparation
- Drive document indexing
- Contacts and relationship context
- Meeting preparation briefs

## Phase 3 — Intelligence and automation

- OpenAI Responses API integration
- Scheduled daily and weekly brief generation
- Project drift and commitment monitoring
- Policy-based approval routing
- Background jobs and webhook processing

## Phase 4 — Finance and organizational authority

- Read-only financial aggregation
- Budget and obligation monitoring
- Payment preparation with approval thresholds
- Contract intake and review routing
- Hiring workflow preparation
- Immutable audit records for consequential actions

## Release rule

ACE gains authority only after the preceding level has produced reliable records and predictable behavior. Observation comes before recommendation, recommendation before preparation, and preparation before delegated execution.
